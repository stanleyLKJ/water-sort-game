## [CURRENT] 当前正式需求

### 核心倒水关卡

- REQ-CORE-001：玩家点击一个非空、未收集水瓶作为源瓶，再点击另一个水瓶作为目标瓶，系统尝试执行倒水；点击已选中的同一水瓶应取消选中。
- REQ-CORE-002：系统必须按经典倒水规则判断合法性：源瓶非空、源/目标不同、二者未收集、目标未满、目标为空或目标顶部真实颜色与源瓶可倒颜色相同。
- REQ-CORE-003：每层水提前拥有真实颜色，初始只显示非空瓶顶部真实颜色，其余未揭示层显示黑色阴影和问号；成功倒水后只揭示源瓶新的顶部层。
- REQ-CORE-004：当水瓶满 4 层、4 层真实颜色相同且 4 层全部已揭示时，该瓶自动飞向并投入关卡内炼药锅，不再参与倒水；仍有任意问号层的同色满瓶不得自动收集；炼药锅调试进度必须按当前关卡目标颜色数量动态显示 4 / 5 / 6 个进度格，并在收集满当前关卡目标颜色数后触发通关。

### [CURRENT] 外层循环与第三阶段第二批改动

- REQ-HOME-001：项目当前启动入口以 `main.tscn` 为准，启动后先显示 `HomeGarden`，不直接进入 `GameScene`。
- REQ-HOME-002：玩家点击“开始游戏”后进入 `FlowerSelect`。`FlowerSelect` 固定显示 6 个格子；当前仅 `pink_rose`、`yellow_rose`、`lavender` 开放，`flower_04` 到 `flower_06` 为待开放灰态占位，点击提示“该花将在后续版本开放”，不得进入 `LevelSelect`。
- REQ-HOME-003：选择开放花后进入 `LevelSelect`，按所选花显示 7 个临时外层关卡。每个开放花第 1 关默认可玩；通关第 N 关后，第 N 关变为已完成锁定，第 N+1 关解锁；已完成关卡不可重复进入并不再给奖励。
- REQ-HOME-004：`[DEPRECATED]` 第二阶段旧出口为 `GameScene` 通关后生成待种植奖励；当前第三阶段第二批已改为外层流程把本局目标花种子 x1 + 对应魔法药剂 x1 写入仓库库存，不进入 `[DEPRECATED]` 旧 `RewardFlower` 四选一奖励花，也不生成 `PendingPlanting`。
- REQ-HOME-005：`[DEPRECATED]` 第二阶段旧规则为 `PendingPlanting` 未完成时阻止再次开始游戏；当前第三阶段第二批通关出口保持 `PendingPlanting` / `HasSeed` / `HasPotion` 为 false，回主页后不得阻止玩家继续点击开始游戏 / 调试药剂入口。
- REQ-HOME-006：主页花位升级为组合批次结构。每个位置最多一批花，一批花可包含多个不同 `flower_id`；同一 `flower_id` 在同一位置最多出现一次；组合 key 按 `pink_rose -> yellow_rose -> lavender` 稳定排序，例如 `pink_rose+yellow_rose`。
- REQ-HOME-007：待种植状态下，空花位显示数字圆圈；已有花位若不包含本次奖励花，也显示数字圆圈并可追加；已有花位若已包含本次奖励花，不显示数字圆圈。只有点击数字圆圈圆形区域才触发，点击背景、花图、slot 父节点或圆圈矩形外角不得触发。
- REQ-HOME-008：每个开放花最多出现在 7 个不同主页位置。某花已满后，`FlowerSelect` 中该花仍显示但变灰，点击提示“该花已种满，请选择其他花”，不得进入 `LevelSelect`。
- REQ-HOME-009：`[DEPRECATED]` 纯运行期外层状态是第二阶段旧口径；当前第三阶段第二批已将每花关卡进度和通关奖励仓库库存写入 `SaveData`，第三阶段第四批基础种植和铲花已写入主页花位组合并更新仓库库存；设置等完整持久化仍待后续分批实现。

### 素材与花 ID

- REQ-ASSET-001：HomeGarden 主页素材显示以 `HomeGarden.tscn` 中保存的可视化节点为权威。每个已确认正式花种、每个主页固定 slot，都必须有可编辑的 `TextureRect` 或等价可视节点；单花显示和组合显示都应该走场景节点，不依赖运行时脚本动态加载贴图。
- 主页素材的位置、缩放、层级、遮挡、anchors、offset、`z_index` 和贴图引用，均由 Godot 编辑器中保存的节点参数决定。`HomeGardenView` 只能根据 `RunSessionState` 显示 / 隐藏这些已有节点，不能作为主页素材布局和贴图来源的权威。
- 多花组合素材缺失时，后续实现应 warning / 隐藏 / 标记待补，不得崩溃；不得临时叠加多个单花素材或动态补图作为正式表现。
- REQ-ASSET-002：目标花选择页素材必须使用选择页专用素材目录，不得把主页 `home_slots` 图混用为选择页展示图。
- 选择页 `FlowerSelect` 的 `select` 素材规则本次暂不改变，仍可保留为后续单独任务。
- 当前已确认正式 `flower_id` 为 `pink_rose`、`yellow_rose`、`lavender`；`flower_04` 到 `flower_06` 为待确认占位 ID，不得猜测真实花名。

## 实现建议与表现要求

- 倒水动画、水流、多点弧线、液体遮罩、花朵生长反馈和药剂倒入表现属于表现层要求，不改变 REQ-CORE-001 到 REQ-CORE-004 的数据规则。
- 第二阶段可以保留 `[DEPRECATED]` 旧 `RewardFlower` 文件作为历史遗留，但不得把旧“四选一随机奖励花”写成当前正式流程。
- `[DEBT]` `Bag*` 命名属于历史命名债务，当前需求语义统一为炼药锅调试进度收集；本次不要求大范围重命名或删除 `Bag*` 文件。
- `GameScene` 顶部四个花盆视觉已废弃；当前药剂调试关卡的正式表现是炼药锅区域，满瓶同色后瓶子应播放飞向炼药锅并倒入/投入的表现。
- `GameScene` 全部颜色完成后，先在关卡内展示本局目标花对应的两个奖励：种子 x1 + 药剂 x1；奖励层需要显示标题、本局目标花名或 `flower_id`、对应花的种子图片、对应花的药剂图片、“种子 x1”、“药剂 x1”和“种植”按钮。奖励层默认停留 3 秒后自动继续；玩家点击“种植”按钮时立即跳过剩余等待时间。展示完成后再由既有 `MainFlowController` 接收 `GameManager.LevelCompleted`。当前第三阶段第二批由 `MainFlowController` 把奖励写入 `SaveData` 仓库库存并回到 `HomeGarden`，不由 `GameScene` / `CauldronView` 直接写仓库或主页状态。奖励花来源仍是 `RunSessionState.SelectedFlowerId`，不在 `GameScene` 内自行选择。

`[DEPRECATED]` 第二阶段代码曾使用 `PendingPlanting` 强制即时种植。`[CURRENT]` 第三阶段第二批已用“奖励写入仓库库存”替代通关后的强制即时种植出口；第三阶段第三批已接入只读 `WarehousePage` 基础版；第三阶段第四批二次纠偏后，“种植页面”按钮不再进入独立 `PlantingPage` 选花页，而是让 `HomeGarden` 进入种植状态：先显示 1-7 数字圆圈，玩家点击位置后弹出该 slot 操作面板，再选择花并从仓库扣减种子和药剂，或对已种植 slot 铲全部 / 铲单种并返还对应库存。`PlantingPage` 文件可保留为历史 / 备用页面，但当前正式种植流程不依赖它。`[DEPRECATED]` 旧 `RewardFlower` 仍为历史遗留，不恢复为正式流程。

### 仓库页面需求目标

第三阶段目标新增 `scenes/warehouse/WarehousePage.tscn` 或等价命名，具体命名在后续实现任务中确认。

仓库页面职责规划：

- 只查看库存，不直接种植。
- 显示每种开放花的种子数量和药剂数量。
- 种子和药剂分开显示，不合并成“可种植次数”。

库存结构目标：

- 按 `flower_id` 分别记录 `seed_count` 和 `potion_count`。
- 当前开放花至少包括 `pink_rose`、`yellow_rose`、`lavender`。
- 后续 `flower_04` 到 `flower_06` 开放后按同一结构扩展。

库存变化规则目标：

- 通关后：所选花 `seed_count + 1`，`potion_count + 1`。
- 种植后：对应花 `seed_count - 1`，`potion_count - 1`。
- 铲花后：被铲花 `seed_count + 1`，`potion_count + 1`。
- 种植条件：同一 `flower_id` 的 `seed_count >= 1` 且 `potion_count >= 1`。

### 种植页面需求目标

第三阶段目标新增 `scenes/planting/PlantingPage.tscn` 或等价命名，具体命名在后续实现任务中确认。

种植页面职责规划：

- 作为“从仓库选择要种的花”的入口，只负责展示开放花库存并选择 `flower_id`。
- 不作为独立花位选择页，不显示或提交 1-7 个 slot 作为正式种植位置。
- 选择可种植花后回到 `HomeGarden`，由主页 1-7 数字圆圈完成种植位置选择。
- 成功点击 `HomeGarden` 数字圆圈后使用仓库库存种花。
- 支持通过 `HomeGarden` 数字圆圈追加花到已有花位。
- 支持铲花后重新种。
- 当前纠偏后不支持“先在 PlantingPage 选花位再选库存花”的正式流程；花位选择必须在 `HomeGarden` 完成。

库存不足规则目标：

- 种植页面仍显示所有已开放花。
- 种子或药剂不足的花灰态。
- 点击灰态花提示“缺少种子或药剂”。
- 不足材料的花不可选择种植。

花位规则延续当前 `HomeGarden` 的 `slot -> flower_id 集合 / batch` 结构。同一花位可包含多种不同 `flower_id`，同一 `flower_id` 在同一花位最多出现一次，组合 key 仍按开放花顺序稳定排序。

`HomeGarden` 数字圆圈显示规则：空 slot 显示；已有花位若不包含当前选择的 `flower_id` 也显示并可追加；已有花位若已经包含当前选择的 `flower_id` 不显示。只有点击数字圆圈圆形区域才触发种植，点击背景、花图、slot 父节点或圆圈矩形外角不得触发。

铲花规则目标：

- 点击已种植花位后弹出铲花选项：铲除此花位全部花，或选择其中一种花铲除。
- 铲除全部时，返还该 slot 内每一种 `flower_id` 的种子 x1 + 药剂 x1。
- 铲除单种时，只返还被铲 `flower_id` 的种子 x1 + 药剂 x1。
- 铲除后更新 slot batch，并刷新 `HomeGarden` / `PlantingPage` 的单花或组合显示。
- 铲除后必须触发自动保存。

### 关卡设计与 LevelGenerator 目标

第三阶段目标是不再长期复用同一个固定测试关卡；每关由可解随机关卡生成器生成，并随关卡推进提升水瓶数量、颜色数量和难度。参数应由 `LevelDifficultyConfig` 或等价配置表控制。

推荐难度配置：

- 第 1-2 关：6 瓶 / 4 色。
- 第 3-5 关：7 瓶 / 5 色。
- 第 6-7 关：8 瓶 / 6 色。

该配置适用于每个开放花的 7 关。当前正式入口已使用“从完成状态反向打乱 + 记录已知解路径 + 有界验证”；为满足视觉揭示顺序第 3 / 4 层不同并给两只空瓶约束下的反向路径保留缓冲移动空间，三档反向打乱步数为 16 / 20 / 24。`LevelGenerator.UseRandomizedLevels` 旧简单随机入口仅作调试兼容保留，已标记为弃用，不用于正式外层关卡流程。

关卡初始布局质量验收适用于 4 / 5 / 6 色正式生成关卡：真实瓶内颜色自底向顶允许 2 连，不允许 3 连或 4 连；初始非空瓶顶层真实颜色按开局暴露信息统计，同一种颜色最多出现 2 个。问号层只是视觉隐藏，数据层真实颜色仍必须参与上述检查。

`LevelSelectView` 只显示入口和状态，不允许写入关卡生成逻辑。`LevelGenerator` 或后续 `LevelConfig` / `LevelDifficultyConfig` 才负责生成关卡数据。

## 项目定位

本项目是一个 2D 休闲益智倒水小游戏 Demo，当前视觉方向统一为“魔法园丁”风格。

玩家通过整理水瓶中的彩色魔法水，让满瓶同色的水自动投入关卡内炼药锅，并更新炼药锅调试进度。旧“花盆收集区 / 顶部四个花盆”只作为第一阶段历史表现说明，不作为当前正式需求语义。

第一版重点是验证核心玩法闭环，不追求完整商业化系统。

## [HISTORICAL] 第一版 Demo 目标（仅供第一阶段追溯）

第一版 Demo 需要验证：

- 玩家可以点击一个水瓶作为源水瓶，再点击另一个水瓶作为目标水瓶。
- 系统能按照倒水规则判断能否倒水。
- 成功倒水后，水瓶状态正确变化。
- 问号层能按规则解锁。
- 满瓶同色后能自动完成收集；当前正式表现应写为“自动投入炼药锅 / 更新炼药锅调试进度”，旧花盆说法仅保留为第一阶段历史说明。
- 收集完成后能触发通关。

第一版优先保证玩法清晰、规则稳定、竖屏展示可用。

## 游戏核心玩法

玩家在游戏页面中看到多个水瓶和关卡内炼药锅调试进度区。

基本操作流程：

1. 点击一个非空、未收集的水瓶作为源水瓶。
2. 源水瓶被选中，并向上移动一点。
3. 再点击另一个水瓶作为目标水瓶。
4. 系统判断是否符合倒水规则。
5. 如果可以倒水，则立即更新水瓶中的水层。
6. 如果不能倒水，则目标水瓶轻微摇晃，并显示“不能倒入”。

点击已选中的同一个水瓶时，取消选中。

## 水瓶数量、容量、颜色数量

- 第一版 Demo 使用 6 个水瓶。
- 每个水瓶最多容纳 4 层水。
- 第一版使用 4 种颜色：红色、蓝色、黄色、绿色。
- 初始关卡允许出现 1 到 2 个空水瓶，方便玩家进行倒水操作。
- 每种颜色在一局中总计 4 层水。

## 问号层机制

每个水瓶最多从下到上包含 4 层水，但玩家初始只能看到每个非空水瓶最上方的真实颜色。

初始显示规则：

| 层级 | 初始显示 |
| --- | --- |
| 当前最上层 | 真实颜色 |
| 其余未解锁层 | 黑色阴影层 + 白色问号 |

规则要求：

- 每一层水都应提前拥有真实颜色。
- 显示时区分真实颜色、是否已解锁、是否为空。
- 当当前可见的上层水被倒走后，下一层问号层解锁，显示真实颜色。
- 已解锁显示过的颜色会一直显示，不会重新变回问号。
- 新解锁的同色层不会在同一次倒水操作中继续被倒出。

## 倒水规则

第一版采用经典倒水规则：

- 源水瓶必须非空。
- 源水瓶和目标水瓶不能是同一个。
- 已收集的水瓶不能作为源水瓶或目标水瓶。
- 目标水瓶未满时才可以倒入。
- 目标水瓶为空时可以倒入。
- 目标水瓶非空时，目标顶部颜色必须与源水瓶要倒出的颜色相同。
- 一次倒水只计算倒水前已经显示出来的顶部连续同色层。
- 实际倒入层数受目标水瓶剩余容量限制。

示例：源水瓶顶部有 3 层已显示红色，目标水瓶顶部也是红色但只剩 2 个空位，则本次只能倒入 2 层红色。

无效倒水反馈：

- 目标水瓶轻微摇晃。
- 显示文字提示“不能倒入”。
- 第一版不做错误音效。

## [DEPRECATED] 旧花盆收集机制（仅供第一阶段历史追溯）

原旧文档曾把“袋子”机制统一改为“花盆收集区”。该说法已被后续“炼药锅调试进度”口径替代，当前正式事实以本文档顶部 `[CURRENT] 当前正式需求` 和 `docs/03_实现文档.md` 顶部快照为准。

旧花盆收集区不是临时倒水容器，而是第一阶段完成水瓶的历史收集区域。

收集区要求：

- `[HISTORICAL]` 顶部显示 4 个花盆。
- 每个花盆对应一种颜色：红色、蓝色、黄色、绿色。
- 当一个水瓶已满 4 层，且 4 层水全部是同一种颜色时，系统自动收集该水瓶。
- 收集后，该水瓶从场上消失，不再参与倒水。
- 对应颜色花盆的收集数量增加。
- 视觉表现为对应颜色花盆长出对应颜色的花。
- 收集后不补新的水瓶。

问号是否已显示不影响收集判断。只要真实数据上满瓶同色，即可被自动收集。

## 关卡生成要求

第一版最终目标是随机生成关卡，并尽量保证有解。

生成要求：

- 总水层数量固定为 16 层。
- 4 种颜色每种正好 4 层。
- 使用 6 个水瓶。
- 保留 1 到 2 个空水瓶。
- 每个非空水瓶初始只显示当前最上层真实颜色。
- 其余未解锁层显示黑色阴影层 + 白色问号。

推荐生成方向：

- 先从完成状态出发，每种颜色组成一个满瓶同色水瓶。
- 再通过合法反向打乱生成初始局面。
- 避免完全随机塞颜色导致无解或体验不佳。

第一版允许先使用固定测试关卡验证玩法，但应明确标记为临时实现。

## 通关条件

第一版不设置失败条件，玩家可以一直尝试。

玩家卡住时，通过“重开”按钮重新开始。

表现要求：

## 倒水与水位表现优化需求

在不修改核心倒水规则的前提下，倒水表现需要从静态或硬直线效果升级为更柔和的表现层动画。

水流表现要求：

- 水流颜色必须使用本次 `PourPlan.Color` 对应颜色。
- 水流从源瓶 `PourPoint` 指向目标瓶口。
- 水流不应是单条硬直线，应使用 3 到 4 个点形成轻微弧线或水束路径。
- 水流需要开启抗锯齿。
- 水流头尾应有渐隐或透明度变化，避免生硬截断。
- 可以增加少量水滴或落点 splash，但不要求真实流体模拟。

瓶内水位表现要求：

- 每瓶最多 4 层水的逻辑保持不变。
- 视觉上水层应连续填充，不再像 4 个分离的硬矩形图块。
- 水层和问号黑色层必须显示在瓶身内部区域，不应明显超出玻璃瓶轮廓。
- 顶部水面可以使用轻微波浪或圆滑边缘。
- 问号层规则和显示语义保持不变。

倒水动画时序要求：

- 合法倒水时，源瓶先移动并倾斜。
- 水流出现后，源瓶水位下降，目标瓶水位上升。
- 动画过程中调用 `PourSystem.ExecutePour()` 修改真实数据。
- 动画结束后刷新所有视图，并继续执行自动收集和胜利判断。
- 动画期间保持输入锁，避免连续点击导致状态错乱。

表现层边界：

- 不把倒水规则写进 `BottleView`。
- 不让表现层保存唯一真实状态。
- `PourSystem`、`BottleData`、`WaterLayer`、`PourPlan`、`PourResult` 的数据规则保持不变。
- 问号层规则保持不变：只统计倒水前已揭示顶部连续同色层，新解锁同色层不能在同一次倒水继续倒出。
- 水流效果应由倒水提交或倒水状态变化信号驱动，表现层只读倒水结果并显示/停止特效。
- 当本次实际移动量小于等于阈值时不显示水流。
- 倒水停止、取消输入或进入 Blocked 状态时，水流必须立即停止。

## 瓶装液体美术规范交付物

为后续设计师、动画师和 AI 绘图修正人员统一执行标准，需要提供一份《瓶装液体表现制作与验收规范（专业版）》信息图。

信息图必须覆盖：

- 容器结构定义：外轮廓、内轮廓、瓶壁厚度、瓶口、瓶底弧线、可见液体区域、不可穿透区域。
- 瓶内遮罩与约束：液体和问号层必须限制在瓶身内腔中，不得穿出瓶壁、瓶底或瓶口外轮廓。
- 液位与透视：空瓶、半瓶、满瓶、多层液体需要统一高度标准，顶部液面符合瓶身透视。
- 出水路径：起点来自源瓶瓶口，终点进入目标瓶口或收集区，路径符合瓶口倾角、重力方向和液体粘稠度。
- 动画同步：开始、持续、结束三段中，源瓶液面下降、目标瓶液面上升，液流粗细、速度和收束自然。
- 液体材质与动态流体拆分：材质关注主色、边缘加深、高光、透明感；动态关注连续流线、重力、惯性、飞溅、拉丝和滴落。
- 整体风格统一：瓶子、液体、UI、图标、色板、光源和高光逻辑属于同一视觉系统。
- 验收与回退：结构问题回到结构和遮罩，液位问题回到液位透视，路径和动画问题回到出水路径与动画同步，质感和风格问题回到材质、动态和风格统一。

该信息图是美术与表现层验收规范，不改变 `PourSystem`、`BottleData`、`WaterLayer`、`PourPlan`、`PourResult` 的核心玩法规则。

## 按美术规范优化现有项目表现

当前 Godot 项目中的瓶内液体、水流路径和动态表现需要按《瓶装液体表现制作与验收规范（专业版）》落地优化。

优化范围：

- 瓶内可见液体区域应更贴合当前玻璃瓶素材的内腔、瓶肩和瓶底弧线。
- 水层和问号层必须继续受同一瓶内裁剪区域约束，不能明显穿出瓶壁或瓶底。
- 水层视觉应连续填充，层间边界清楚但不过硬，顶部液面保留轻微波浪或弧面。
- 满瓶状态仍需保留瓶口空间，不允许液体填进瓶口外轮廓。
- 倒水水流应从源瓶瓶口发出，进入目标瓶口，路径符合倾角与重力方向。
- 水流需要保留抗锯齿、头尾渐隐、自然粗细变化，并补充适量末端滴落或收束表现。
- 颜色应降低过饱和风险，保持魔法水、玻璃瓶、花盆和 UI 同一视觉系统。

本优化只属于表现层升级，不改变倒水规则、问号层揭示规则、自动收集规则和胜利条件。

## 液体遮罩与瓶子分层方案

为避免继续用代码猜测半写实玻璃瓶内腔，瓶装液体表现应改为“瓶子前景 / 液体遮罩 / 液体层”的方案。

正式方向：

- 液体形状由 `LiquidMask` 控制，不再由每个水层单独拟合瓶身轮廓。
- 水层本身优先使用水平矩形填充，超出瓶身的部分由遮罩裁掉。
- 玻璃瓶前景应覆盖在液体之上，用于保留瓶口、瓶壁、高光和底部玻璃质感。
- 后续若有正式拆分素材，应提供 `BottleBack`、`BottleFront` 和 `LiquidMask`。
- 当前过渡版本可以使用完整瓶子素材作为前景玻璃层，并使用 `assets/bottles/bottle_liquid_mask.png` 作为液体遮罩。
- 美术或开发者可直接替换 `bottle_liquid_mask.png` 来调整液体可见区域，不需要修改倒水规则。

## 第二阶段目标

第二阶段不再继续无限打磨第一版的单局倒水表现，而是从“第一版可玩倒水 Demo”升级为“花园功能主页 + 目标花选择 + 药剂调试关卡 + 手动种植”的小作品原型。

第二阶段的核心目标是建立外层循环：

```text
花园主页 -> 开始游戏 -> 选择目标花 -> 调试魔法药剂 -> 通关获得目标花种子和对应药剂 -> 回到花园主页 -> 选择花位种植 -> 倒入药剂 -> 花位长出对应花
```

第一版核心倒水玩法作为第二阶段的第 1 关内容继续保留。第二阶段语义上，现有倒水关卡是“调试魔法药剂”的关卡内容。第二阶段新增主页、目标花选择、通关奖励和手动种植流程时，不应破坏第一版已经验证过的倒水规则、问号层规则、自动收集规则、胜利判断和重开功能。

第二阶段项目入口要求：

- 当前项目实际启动主场景以 `main.tscn` 为准。
- `main.tscn` 作为第二阶段总入口和流程容器。
- 不要把花园主页、关卡选择、目标花选择、倒水关卡全部继续堆进 `main.tscn`。
- 第二阶段优先将 `HomeGarden`、`LevelSelect`、`FlowerSelect` 作为独立子场景或独立根节点管理。
- 现有倒水关卡应作为第 1 关药剂调试内容接入第二阶段流程，而不是替代 `main.tscn` 的总入口职责。

### 花园功能主页

- 游戏启动后先进入花园主页，不再直接进入倒水游戏页面。
- 花园主页不是单纯菜单，而是功能入口 + 花园展示页。
- 花园主页需要展示柔和、水彩感的魔法花园氛围。
- 当前美术接入版先使用 7 个固定粉玫瑰花位。
- 18 个固定花位作为后续扩展目标保留，当前不作为本版运行容量。
- 通关回到主页后，玩家需要选择一个可操作花位进行种植或追加；当前正式交互是点击该花位上显示的数字圆圈按钮，不再允许点击整个透明花位热区触发种植。
- 种植 / 追加流程为：选择空花位或不含本次奖励花的已有花位 -> 放入本局目标花对应种子 -> 倒入本局调试完成的对应魔法药剂 -> 花位显示对应单花或组合。
- 允许同一种花重复出现。
- 允许同一种花重复种植到不同花位。
- 玩家暂时不能自由拖动花或自由拖拽种子、药剂。
- 暂时不做随机摆放。
- 暂时不做花园扩建、分页花园、图鉴、花朵升级、稀有度或本地存档。
- 待种植状态下，空花位以及不含本次奖励花的已有花位显示 1 到 7 的数字圆圈按钮；已包含本次奖励花的花位不显示。只有点击数字圆圈按钮的圆形区域才完成种植或追加并清除待种植状态，点击背景、花图、slot 大区域或圆圈矩形外角不触发种植。

### 主页按钮

- 主页右下角预留木板功能区。
- 本次只保留“开始游戏”入口；“选择关卡”按钮暂时隐藏并禁用，但不从场景删除。
- 点击“开始游戏”后，不是直接进入倒水关卡，而是先进入“目标花选择界面”。
- 如果木板素材暂时没有接入，可以先用两个普通 `Button` 放在右下角。
- 按钮不能遮挡当前 7 个固定花位的主要展示区域；后续扩展到 18 个花位时同样适用。
- 后续接入木板素材后，再替换普通按钮表现。

### 关卡选择

- 第二阶段采用临时 21 关外层结构。
- 选择开放花后进入 `LevelSelect`，按所选花显示 7 个关卡。
- 每个开放花第 1 关默认可玩；通关第 N 关后第 N 关锁定，第 N+1 关解锁。
- 已完成关卡和未解锁关卡灰态 / 锁定，不可进入。
- 不做真实 21 套不同关卡数据，不做星级、关卡地图或正式多关卡内容。
- 任意当前可玩关进入后均复用现有倒水关卡。

### 目标花选择与药剂调试

- 目标花选择界面展示 6 种基础花。
- 玩家选择其中 1 种作为本局目标花。
- 选择开放目标花后，先进入 `LevelSelect`；玩家选择该花当前可玩关后，才进入现有 `GameScene.tscn` 倒水关卡。
- 第二阶段语义上，`GameScene.tscn` 是“调试魔法药剂”的关卡。
- 注意：`GameScene` 内部原有顶部四个花盆视觉已废弃，当前正式表现是炼药锅调试进度区；它只代表药剂调试关卡的完成进度，不等同于 `HomeGarden` 主页中的种植花位。当前主页使用 7 个固定粉玫瑰花位，18 个花位作为后续扩展目标保留。主页花朵只能通过“通关获得种子和药剂 -> 回到主页选择空花位种植”产生。
- 通关后不再进入“四选一随机奖励花”流程。
- 通关奖励固定为：本局选择花朵对应的种子 + 本局调试完成的对应魔法药剂。
- 回到主页后，玩家需要选择一个可操作花位进行种植或追加。
- 同一花最多出现在 7 个不同主页位置；该花种满后在 `FlowerSelect` 灰态提示。整体花园不再以“7 个位置都有花”作为是否能追加的判断。
- `GameScene` / 药剂调试关卡被 `MainFlowController` 管理时，关卡内除“重开”外还需要提供“退出 / 返回”入口。玩家点击退出后返回当前目标花的 `LevelSelect`，不触发通关、不生成 `PendingPlanting`、不发放种子或药剂、不改变当前关卡完成状态，也不清空当前外层 `SelectedFlowerId`。
- `GameScene` 单独运行用于调试时，退出入口可以隐藏、禁用或只输出 warning，但不得崩溃。
- `GameScene` 中的炼药锅进度、提示文字、胜利弹窗、奖励文本和调试按钮文字必须在手机竖屏下清楚可读；低对比度白字应通过描边、深色底板或深棕 / 深紫文字优化，不应遮挡瓶子、炼药锅或奖励内容。

### 第二阶段素材需求清单

第二阶段素材接入必须区分主页背景、主页已种植花位贴图和目标花选择页展示素材，不能混用。

主页 `HomeGarden` 需要：

- 主页背景素材，运行路径统一放在 `res://assets/home/backgrounds/`。
- 六种花的主页花位贴图。当前运行容量为 7 个主页固定花位，因此每一种花都需要 7 张主页固定位置贴图，用于适配不同花位的位置、透视、缩放和遮挡差异。
- 主页花位贴图可继续按素材归档需要放在 `res://assets/flowers/{flower_id}/home_slots/{flower_id}_slot_01.png` 到 `res://assets/flowers/{flower_id}/home_slots/{flower_id}_slot_07.png`，但正式主页显示不以脚本运行时动态读取该目录为权威。
- 主页花位素材接入不能只停留在 PNG 文件和运行时动态加载；每个已确认正式花种、每个主页固定 slot 都必须在 `HomeGarden.tscn` 中拥有可编辑的 `TextureRect` 或等价可视节点。
- 主页固定花位由“slot 锚点 / 点击热区”和“花种可视化贴图节点”组成。现有 `PinkRoseSlot_01` 到 `PinkRoseSlot_07` 是历史节点名，当前语义是 7 个固定主页花位，不只代表粉玫瑰。
- 每个 slot 下应有花种视觉容器，例如 `FlowerVisualRoot`；已确认花种应拥有独立贴图节点，例如 `PinkRoseTexture`、`YellowRoseTexture`。
- 同一个 slot 下，不同花种的 `TextureRect` 可以拥有不同 anchors、offset、scale、`z_index` 和 texture 引用，用于适配透视、遮挡和构图差异，并允许开发者在 Godot 编辑器中直接选中节点人工调整；这些场景节点参数是主页素材布局和贴图来源的正式权威。
- 单花显示和组合显示都应走 `HomeGarden.tscn` 中的可视化节点；`HomeGardenView` 后续只根据 `RunSessionState` 显示 / 隐藏已有节点，不动态加载主页贴图、不动态创建主页花图、不用代码决定主页素材布局。
- 18 个主页花位仍作为后续扩展目标保留，当前不作为本版运行容量。

目标花选择页 `FlowerSelect` 需要：

- 六种花选择展示素材。
- 每种花至少 1 张选择页展示图或卡片图。
- 选择页展示素材推荐目录为 `res://assets/flowers/{flower_id}/select/{flower_id}_select.png`。

通关奖励道具素材需要：

- 每个开放花需要 1 张种子图和 1 张药剂图，用于 `HomeGarden` 的 `PendingPlanting` 点击后临时种植 / 追加动画。
- 奖励道具正式运行资源目录为 `res://assets/flowers/{flower_id}/items/`。
- 开放花奖励道具命名为 `{flower_id}_seed.png` 和 `{flower_id}_potion.png`，当前仅允许 `pink_rose`、`yellow_rose`、`lavender`。
- 该类素材只用于点击可操作数字圆圈后的临时表现，不在主页常驻展示，不属于主页已种植花位 `home_slots`，也不属于 `FlowerSelect` 的 `select` 展示素材。
- `RunSessionState` 仍只保存 `flower_id`、`HasSeed`、`HasPotion`、`PendingPlantingFlowerId` 等运行状态，不保存图片路径、节点路径或 Godot 节点引用。

当前六种基础花 ID 口径：

| flower_id | 显示名 | 状态 |
| --- | --- | --- |
| `pink_rose` | 粉玫瑰 | 已确认正式花 |
| `yellow_rose` | 黄玫瑰 | 已确认正式花，替换原 `flower_02` 占位 |
| `lavender` | 薰衣草 | 已确认正式花，替换原 `flower_03` 占位 |
| `flower_04` | 待定花 04 | 待确认占位 |
| `flower_05` | 待定花 05 | 待确认占位 |
| `flower_06` | 待定花 06 | 待确认占位 |

`flower_02` 占位已被 `yellow_rose` 替换，不再作为当前六种基础花之一。`flower_03` 占位已被 `lavender` / 薰衣草替换，不再作为当前六种基础花之一。除 `pink_rose`、`yellow_rose`、`lavender` 外，其余 3 种花的真实名称尚未确认。文档、配置和素材接入任务不得自行猜测玫瑰、郁金香、百合等具体花名；在真实名称确认前，只允许使用 `flower_04` 到 `flower_06` 作为稳定占位 ID。

未确认真实花名的 `flower_04` 到 `flower_06` 不需要提前创建完整主页可视化贴图节点；只有正式确认并接入素材的 `flower_id` 才需要在 `HomeGarden.tscn` 中补齐 7 个可调贴图节点。

### [DEPRECATED] 旧奖励花逻辑说明（已废弃）

- “通关第 1 关后直接进入奖励花选择界面”是旧第二阶段方案。
- “从 6 种花中随机抽出 4 种展示给玩家，玩家选择其中 1 朵作为奖励”是旧第二阶段方案。
- “被选择的花自动加入花园主页的下一个固定花位”是旧第二阶段方案。
- 上述随机四选一奖励花流程不再是正式需求，后续实现应以“开局选择目标花 -> 通关获得对应种子和药剂 -> 回主页手动选择花位种植”为准。
- 第二阶段仍不做抽卡动画、花朵属性、图鉴完成度、稀有度。

### 运行期花园状态

- 本次运行期间，玩家已种植的花保留在主页花园中。
- 关闭游戏后，下次重新打开从初始花园状态开始。
- 第二阶段不做本地保存，不做正式存档。
- 存档系统列为第三阶段或后续阶段内容。

### 花种种满后的临时规则

- 当前美术接入版运行容量为 7 个主页固定位置。
- 每个开放花最多出现在 7 个不同主页位置中。
- 某花已出现在 7 个不同位置后，该花视为种满。
- 种满后该花在 `FlowerSelect` 中仍显示，但变灰态；点击提示“该花已种满，请选择其他花”，不进入 `LevelSelect`。
- 判断是否种满只看该 `flower_id` 出现于几个不同 slot，不看单个 slot 内组合数量。
- 不做自动替换、不做删除花、不做扩建。

## [HISTORICAL] 第一版验收标准（仅供第一阶段追溯）

第一版验收标准只用于第一阶段历史验收，不作为第二阶段启动流程和总入口判断依据。

第一版 Demo 完成后，需要满足：

- 游戏进入后直接显示游戏页面。
- 游戏画面适配手机竖屏展示。
- 页面顶部有 4 个颜色花盆。
- 页面中下方有 6 个水瓶，两排排列，每排 3 个。
- 每个水瓶最多有 4 层水。
- 每种颜色总计 4 层。
- 非空水瓶初始最上层显示真实颜色，未解锁层显示黑色阴影 + 白色问号。
- 玩家可以点击源水瓶，再点击目标水瓶进行倒水。
- 倒水遵守经典规则。
- 一次只倒出倒水前可见的顶部连续同色层。
- 新解锁的同色问号层不会自动继续倒出。
- 已解锁颜色会一直显示。
- 无效倒水时，目标水瓶摇晃，并显示“不能倒入”。
- `[HISTORICAL]` 满瓶同色水瓶会自动消失，并进入对应颜色花盆。
- `[HISTORICAL]` 进入花盆收集区后不补新水瓶。
- 4 种颜色完成收集后，弹出胜利提示。
- 游戏页面有重开按钮，重开后能重新开始一局。
- 第一版不需要真实流体模拟、音效、撤销、步数统计和首页。
